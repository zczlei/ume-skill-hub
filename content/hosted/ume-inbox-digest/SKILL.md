# 收件箱分流（ume-inbox-digest）

参考 ClawHub inbox-triage，面向手机通知与聊天，而不是桌面 IMAP CLI。

## 何时使用

通知堆满、出差归来、开会结束后要快速知道「什么必须回」。

## 步骤

1. 读取通知流（`list_active_notifications` / `list_recent_notifications` 或已有 notification skill）。
2. 分组：
   - **紧急**：验证码、银行风控、未接来电、即将开始的会议
   - **待回复**：真人聊天、工作@、快递需取件
   - **可延后/可忽略**：营销、系统更新、社交媒体点赞
3. 输出短摘要（手机可读）：每类最多 3–5 条，带 App/发送方。
4. 对「待回复」给出**一句建议回复草稿**（用户确认后再发；发信走 `ume_whatsapp_send` / 短信 / 对应 App，默认不自动点发送）。
5. OTP 类：只提示「有验证码通知」，**不要朗读或外传完整验证码**，除非用户明确要求看这一条。

## 边界

- 依赖通知使用权；未授权时明确说明并引导设置。
- 不批量自动回复、不批量归档未知 App。
